## 为什么不能只靠串口

串口只能**看**和**发字节**（进 U-Boot、发 reset）。如果 boot 分区的写入被打断：

- 引导区内容不完整 → U-Boot 找不到可启动内核；
- 这时串口只能停在 U-Boot 提示符，**不能把固件变回去**；
- 唯一恢复手段是 **USB 线刷**（Amlogic USB Burning Tool + 整盘镜像 + 短接进 maskrom）。

所以真正的门槛不是串口，而是「线刷工具 + 驱动 + 人能在设备旁短接」。

## 测试 1：写 boot 中途掉电

1. 串口 `watch` 全程录制（只收不发）；
2. 设备侧 `dry_run=0`、`force=1`，缓存包已校验；
3. 运行 `upgrade --reboot --force`，同时 tail 升级日志；
4. 出现 `boot` 写入标记时**立即断电**（或 `echo b > /proc/sysrq-trigger` 硬复位）；
5. 上电观察串口：
   - 出现 `Starting kernel` → 未击中窗口，重试；
   - 停在 U-Boot / 无输出 → 命中，执行线刷恢复；
6. 记录：断电时刻、日志末 20 行、串口全文、恢复耗时。

**窗口极窄**：boot 只有 5.7 MB，dd 大约 1–2 秒。命中率低，可能要多次尝试，每次都可能砖。

## 测试 2：回滚中途掉电

前置：先用一次正常升级生成 L2 快照（当前未实现，需先补快照能力）。
在 `rollback` 写配置/写 boot 的过程中断电，验证：
- 状态文件是否停在 `writing_boot`；
- 下次启动能否识别「未完成」并拒绝自动继续；
- 配置是否可用 L1 备份恢复。

## 更安全的替代（建议先做）

在**文件模拟的 boot 分区**上跑同一段逻辑，不碰真机：

```sh
# 造一个 16MB 的“假 boot”
dd if=/dev/zero of=/tmp/fakeboot.img bs=1M count=16
mkfs.ext4 /tmp/fakeboot.img
mkdir -p /mnt/fakeboot && mount -o loop /tmp/fakeboot.img /mnt/fakeboot
# 把写入流程指向 /mnt/fakeboot，在中途 kill -9 / 卸载
```

它能验证：中断检测、状态判定、恢复分支；**不能**验证 U-Boot 行为与真实掉电语义。

## 2026-11-26 09:30 恢复演练受阻（重要）

- 驱动绑上后，设备进入烧录模式已被 Windows 正确识别：`WorldCup Device`（`VID_1B8E&PID_C003`）状态 OK，串口端口从 COM4 变为 COM5。
- 但**烧录需要点击工具里的 Start 才会开始**，GUI 自动化被虚拟桌面授权（需要 Windows 登录密码）挡住，无法代点。
- 结果：设备停在 U-Boot 的 USB burn 等待里，不自动引导；禁用 USB 设备、串口盲发 `reset` 都无效。**只能断电 5 秒再上电**，才会走正常引导。
- 教训：进入烧录模式前必须先确保「Start 已经处于等待」；否则设备会卡在 burn wait。

## 2026-11-26 09:57 恢复演练成功（关键事实）

- 串口实录：`Downloading %1→100` → `msg:VERIFY OK` → `BULKcmd[save_setting]` → `Set upgrade_step to 2` → `saveenv` → `BULKcmd[burn_complete 3]` → `msg:Pls un-plug USB line to poweroff`。
- 结论：**整盘线刷恢复路径已实证可用**（USB Burning Tool + 402MB 工厂镜像）。
- 设备所有者补充的关键事实：**双公头 USB 线插着时，OneCloud 每次上电都会进入线刷模式，不会正常引导；必须拔线才会从 eMMC 启动。**
  - 这意味着：线刷恢复不需要短接，插线 + 上电即可；
  - 也意味着：日常使用/做升级测试时必须拔掉双公头线，否则设备“假死”在烧录等待。
- 恢复演练流程因此固定为：插线 → 上电 → 工具 Start → 烧录 → 拔线 → 重新上电。


## 2026-11-26 10:20 写 boot 中断实测

- 复位发生在 `resize2fs` 之后、boot 写入之前（日志无 `更新 boot 分区`），boot 未受损，设备正常启动；状态判 `failed/H1`，不自动继续。

- 建议：若要验证 boot 半写状态，用**确定性注入**（把截断的 boot 包写到 boot 分区）替代掐时间，再走线刷恢复；恢复路径已实证。
