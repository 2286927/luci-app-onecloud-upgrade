# 故障救援

前提：这只应用**不改变**设备自身的升级机制，写入仍由 `/usr/bin/upgrade` 完成。所以救砖路径与原来一致。

## 先判断处在哪一步

```sh
/usr/libexec/fwupgrade/fwupgradectl status
```

| 阶段 | 含义 | 处置 |
|---|---|---|
| `idle / last_result=ok` | 正常 | 无 |
| `writing_boot` | 已进不可逆段 | **不要断电**，等它重启 |
| `boot_written` | 写入完成、重启已调度 | 等 1–2 分钟；若 uptime 没归零，手动 `reboot` |
| `last_result=failed, mixed_state=H1` | 写入后未重启，可能混合态 | 先 `reboot`，看能否起来 |
| `unknown` | 状态文件损坏或不可判定 | 只读核对，不要直接重试 |

`status` 轮询会自动判定：`boot_id` 未变化且超过 15 分钟 → 直接判失败，不会假装成功。

## 配置丢了 / 配错了（L1）

```sh
# 列出备份
/usr/libexec/fwupgrade/fwupgradectl backups

# 恢复（默认合并：只覆盖备份里有的文件）
/usr/libexec/fwupgrade/fwupgradectl rollback --confirm <备份ID>

# 整目录替换（会把当前新增的配置也删掉，谨慎）
/usr/libexec/fwupgrade/fwupgradectl rollback --confirm <备份ID> --replace
```

回滚前会自动给当前配置打快照到 `/opt/fwupgrade/rollback/<ts>-pre/`，恢复后逐文件 `cmp` 校验。

**注意**：如果备份里含 `network` / `firewall` / `uhttpd`，恢复可能切断当前连接。优先在串口或本地终端旁操作。

## 系统起不来（L2/L3）

- 本应用**不提供**一键系统回滚：OneCloud 没有 A/B 分区，boot 分区余量只有约 2.3 MB，放不下第二份内核。
- 升级前的 boot 备份在 `/opt/upgrade-backup-<时间戳>/boot-p1.img.gz`（设备脚本生成），可 `gzip -t` 验证完整性；恢复要在能启动的系统里做。
- **boot 分区被写坏 → 一定起不来**（已实测，2026-11-26）：串口表现为
  ```
  ** Unable to use mmc 0:1 for fatload **
  ** Unable to use mmc 1:1 for fatload **
  ** Invalid boot device **
  m8b_onecloud#
  ```
  随后约 15 s 看门狗复位，形成「复位 → 提示符 → 复位」循环。
- 恢复手段只有两条：
  1. **线刷**（已验证两次）：双公头 USB 线插上 → 上电（自动进 burn 模式）→ Amlogic USB Burning Tool 点 Start → 烧 402MB 工厂镜像。**不需要短接**，双公头线插着时每次上电都会进烧录模式；因此日常测试要拔线，否则设备会"假死"在 burn 等待。
  2. **U-Boot 提示符下人工修**：上电后有 `Hit Enter key to stop autoboot -- : 3 2 1 0`，3 s 内按 Enter 进 `m8b_onecloud#`，可用 `fatload/fatwrite`（U 盘）或 `tftp` 把 `uImage`/`dtb`/`boot.scr` 写回 boot 分区。

## 引导现场（实测参数，2026-11-26）

| 项 | 值 |
|---|---|
| eMMC 分区（U-Boot 视角） | bootloader 0/4MB、reserved 4/4MB、cache 8MB/0、env 8MB/4MB、resource 12MB/4MB、**boot 16MB/256MB**、**rootfs 272MB/7GB** |
| Linux 侧 | `mmcblk1p1` start=32768 size=524288（256MB 分区，内含 16MB FAT16）；`mmcblk1p2` start=557056 size=14712832 |
| boot.scr（797 B） | `bootargs_emmc`：`root=/dev/mmcblk1p2 rootwait ro console=ttyAML0,115200n8` → `fatload mmc 1 uInitrd`（缺失不影响）→ `fatload mmc 1 uImage` → `fatload mmc 1 dtb`，dtb 失败退 `imgread dtb boot` |
| 每次上电 | 先进 `Enter USB burn` 等约 3 s（`Try connect time out 1001, 1000, 789`），无工具应答才走 bootcmd |
| 第二块设备 | `mmcblk0` = SD 卡槽（实测 LX128 128GB），不是启动盘，`fatload mmc 0:1` 恒失败，可忽略 |

排障只看一行：**串口里 `reading boot.scr` / `reading uImage` 是否成功**。`** Unable to use mmc 1:1 for fatload **` 就等于 boot 分区不可读。

## 串口

- 参数：`115200 8N1`，控制台 `ttyAML0`（`/proc/cmdline` 可确认）。
- 只读观察用 `serial-ops watch`，不要在 U-Boot 的 autoboot 窗口发字节（会被打断自动启动）。

## 三条硬规则

1. 进入 `writing_boot` 后**绝不断电**。
2. 失败不自动重试——同一版本连续失败两次就停下来核对，而不是再点一次。
3. 回滚本身也是一次写入；回滚前先确认串口/线刷手段在位。
