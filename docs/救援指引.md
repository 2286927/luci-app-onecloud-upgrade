# 故障救援

前提：这只应用**不改变**设备自身的升级机制，写入仍由 `/usr/bin/upgrade` 完成。所以救砖路径与原来一致。

## 先判断处在哪一步

```sh
/usr/libexec/fwupgrade/fwupgradectl status
```

| 阶段 | 含义 | 处置 |
|---|---|---|
| `idle / last_result=ok` | 正常 | 无 |
| `writing_boot` | 已进不可逆段 | **不要断电**，等它重启 |
| `boot_written` | 写入完成、重启已调度 | 等 1–2 分钟；若 uptime 没归零，手动 `reboot` |
| `last_result=failed, mixed_state=H1` | 写入后未重启，可能混合态 | 先 `reboot`，看能否起来 |
| `unknown` | 状态文件损坏或不可判定 | 只读核对，不要直接重试 |

`status` 轮询会自动判定：`boot_id` 未变化且超过 15 分钟 → 直接判失败，不会假装成功。

## 配置丢了 / 配错了（L1）

```sh
# 列出备份
/usr/libexec/fwupgrade/fwupgradectl backups

# 恢复（默认合并：只覆盖备份里有的文件）
/usr/libexec/fwupgrade/fwupgradectl rollback --confirm <备份ID>

# 整目录替换（会把当前新增的配置也删掉，谨慎）
/usr/libexec/fwupgrade/fwupgradectl rollback --confirm <备份ID> --replace
```

回滚前会自动给当前配置打快照到 `/opt/fwupgrade/rollback/<ts>-pre/`，恢复后逐文件 `cmp` 校验。

**注意**：如果备份里含 `network` / `firewall` / `uhttpd`，恢复可能切断当前连接。优先在串口或本地终端旁操作。

## 系统起不来（L2/L3）

- 本应用**不提供**一键系统回滚：OneCloud 没有 A/B 分区，boot 分区余量只有约 2.3 MB，放不下第二份内核。
- 升级前的 boot 备份在 `/opt/upgrade-backup-<时间戳>/boot-p1.img.gz`（设备脚本生成），可 `gzip -t` 验证完整性；恢复要在能启动的系统里做。
- 完全起不来时只能线刷：Amlogic USB Burning Tool + 整盘镜像（短接进 maskrom），或用 U 盘引导。

## 串口

- 参数：`115200 8N1`，控制台 `ttyAML0`（`/proc/cmdline` 可确认）。
- 只读观察用 `serial-ops watch`，不要在 U-Boot 的 autoboot 窗口发字节（会被打断自动启动）。

## 三条硬规则

1. 进入 `writing_boot` 后**绝不断电**。
2. 失败不自动重试——同一版本连续失败两次就停下来核对，而不是再点一次。
3. 回滚本身也是一次写入；回滚前先确认串口/线刷手段在位。
