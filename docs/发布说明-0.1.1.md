# 发布说明 v0.1.1（2026-11-26）

补丁版本，修的都是「用另一个仓库的固件实测」时暴露的问题。升级路径与配置兼容 v0.1.0，直接覆盖安装即可。

## 修了什么

### 1. 指定 Release tag（新能力）

配置项 `onecloud-upgrade.main.tag`，页面「固件源」里新增输入框。

一个仓库发多个机型时（如 `ImmortalWrt-MultiDevice`，每个机型一个 Release），`/releases/latest` 指向的是**最后发布的那个机型**，与本机无关。填了 tag 就按 `/releases/tags/<tag>` 精确取。

### 2. 写入真正按清单执行

以前 `flashers/onecloud.sh` 只调用 `/usr/bin/upgrade --reboot`，而设备脚本自己去 `/etc/oc-repo` 找目标。于是出现「应用说可升 X，脚本按自己的仓库判定已是最新，exit 0」，一个字节没写。

现在改成：

```sh
OC_REPO="<应用配置的仓库>" /usr/bin/upgrade --reboot --url="<清单里的 rootfs 直链>"
```

`--url` 锁定 Release（脚本从 URL 的 `/download/<TAG>/` 派生目标版本），`OC_REPO` 让脚本去同一仓库取该 TAG 的 sha256。

### 3. 「已是最新」不再冒充写入成功

`worker.sh` 在设备脚本返回 0 后，检查 `/opt/oc-upgrade.last` 末条记录；若是本轮的 `uptodate`，立刻判 `failed` 并写明「设备脚本判定已是最新、未写入」，不用再等 15 分钟超时。

### 4. 陈旧签名误报

`check` 现在把 `manifest.json` 与 `manifest.json.sig` 一起清，provider 解析前也清残留 `.sig`。从「有签名的源」切到「无签名的源」不会再误报「清单签名校验失败（rc=6）」。

## 已知限制（不变）

- 离线升级仍不可用：设备脚本按 TAG 调 GitHub API 取 sha256，断网即失败。跨仓库升级需要网络，但不再要求目标仓库是「官方」那个。
- 无 `manifest.json` 的仓库走兼容模式：版本从 tag 推导、sha256 取 Release digest、target 不做校验、签名跳过（除非 `require_signature=1`）。
- 镜像未打包本应用时，在线升级会冲掉 apk 注册（文件仍在、功能照常）；重装需 `--force-overwrite`。

## 实测

`26.11.17_17.35.18`（官方仓）→ `26.11.18_16.27.30`（官方仓）→ **`26.11.21_08.59.21`（ImmortalWrt-MultiDevice）**，跨仓库升级成功：boot_id 变化、`reboot-ok` 记录的 `sha-rootfs=e718a2167b84` / `sha-boot=904753f14a45` 与该 Release 官方摘要一致、`/etc/config` 40 个文件保留。
