# 兼容性与支持范围

## 支持

| 项 | 范围 |
|---|---|
| 硬件 | OneCloud（Amlogic S805 / meson8b / eMMC） |
| 固件 | ImmortalWrt 25.12（`25.12-SNAPSHOT` 实测） |
| 包管理 | apk（25.12 起） |
| LuCI | ucode + JS 视图（25.12 默认） |
| 包架构 | `noarch`（纯 shell / ucode / JS / JSON，无编译产物） |

## 运行依赖

| 依赖 | 用途 | 设备是否自带（OneCloud 25.12） |
|---|---|---|
| `ucode` + `ucode-mod-fs` + `ucode-mod-uci` | 清单解析 | 是 |
| `jsonfilter` | rpcd 参数解析 | 是 |
| `luci-base` | 页面框架 | 是 |
| `/usr/bin/upgrade` + `/usr/lib/oc-upgrade.sh` | 真正的下载/校验/写入 | 是（固件内置） |

缺任何一个，`check` 或页面会明确报错，不会静默继续。

## 不支持

- **没有 sysupgrade 镜像的机型**：OneCloud 本身就没有 `IMAGE/sysupgrade`，这是本应用存在的原因；反过来，标准 OpenWrt 机型也不该用本应用（请用 `luci-app-attendedsysupgrade` / `owut`）。
- **OpenWrt 23.05 及以下 / opkg**：只出 apk，不提供 ipk。
- **Lua 版 LuCI**（19.07–21.02）：视图是 JS，老前端白屏。
- **NAND / 双分区 / 其他 SoC**：`onecloud-emmc` flasher 是唯一写入实现。

## 已验证矩阵（2026-11-23）

| 场景 | 结果 |
|---|---|
| 25.12-SNAPSHOT / eMMC / apk | 检测、dry-run、真实重刷（T4）、备份、回滚（临时目录）、诊断 均通过 |
| x86/64 25.12 SDK 构建 | 5 个 apk 全部产出，`arch=noarch` |
| apk 安装 | `apk add --allow-untrusted` 成功，文件纳入包管理 |
| 故障注入 | 配置缺失 / 缺 boot 资产 / 平台不符 / 空间不足 / 重复 apply / 非法备份 ID 全部按预期拒绝 |

## 已知限制

- 签名：已支持 usign 清单签名；默认 `require_signature=0`（有签名则校验、无签名放行），设为 `1` 即强制。
- 通道：stable（latest）与 beta/dev（releases 列表第一个非 draft）均可用；离线升级暂不支持（设备脚本强制取 API 摘要）。
- 进度是**阶段进度**（预检/备份/写入/收尾），不是字节进度。
- 应用不会自动进入固件；要么按 [固件接入](固件接入.md) 打进镜像，要么手工装 apk。
- **界面仅中文**：i18n 机制未接入（避免重新引入 luci.mk 的注册问题），英文用户请看 README 的 English 摘要。

## 破坏性验证（2026-11-26，实机）

| 场景 | 结果 |
|---|---|
| boot 分区写入损坏（2MB 随机覆盖后复位） | **不可引导**：U-Boot `fatload mmc 1:1` 失败 → `Invalid boot device` → 掉 `m8b_onecloud#`，约 15s 看门狗复位循环 |
| 线刷恢复（USB Burning Tool + 402MB 工厂镜像） | 成功两次：`Downloading 1→100` → `VERIFY OK` → `burn_complete 3` |
| 真实在线升级（v0.1.0，`dry_run=0`） | 成功：`26.11.17_17.35.18` → `26.11.18_16.27.30`，boot_id 变化 + `reboot-ok` + 版本一致，`/etc/config` 40 文件保留 |
| 回滚中途强杀（250MB 写入窗口内 `kill -9`） | 合并与 replace 两条路径均未损坏配置：留 `phase=rollback` 标记、无截断文件、`status` 收口 `failed/C1`、重跑幂等成功 |
| 升级后再检测 | `update_available=false`，不重复提示 |

结论不变：**没有 A/B、没有自愈**。写坏 boot 只能线刷（双公头线插上即进烧录模式，无需短接），或掉到 `m8b_onecloud#` 时人工修（3 秒 autoboot 窗口内按 Enter 可进提示符）。

## 设备侧脚本会被 cron 改写（不是故障）

固件里的 `/usr/lib/oc-upgrade.sh` 有两行镜像加速列表，设备上装的 `up-mirror-maint`（`17 4 * * *`）会每天测速后重排这两行，导致文件大小在 51,430 / 51,432 字节之间变化（sha 也随之变）。

实测两者**代码完全相同，只差这两行**：

| | GH_MIRRORS | API_MIRRORS |
|---|---|---|
| 工厂默认 | gh-proxy.org → gh.monlor.com → gh-proxy.com → ghproxy.imciel.com | gh-proxy.org → gh-proxy.com |
| 被本机 cron 重排后 | gh.monlor.com → gh-proxy.org → ghproxy.imciel.com → ghfast.top | gh-proxy.com → gh-proxy.org |

后果只是镜像顺序变化，不影响校验与写入逻辑。应用里的脚本版本闸门仍应保留（确保接口语义匹配），但**不能把 sha 变化当成"脚本被换"的证据**——先比对镜像行。
