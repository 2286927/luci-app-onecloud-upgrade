# 安装与卸载

只支持 OneCloud（ImmortalWrt 25.12 / apk / ucode LuCI）。不支持的固件不要装。

## 方式一：随固件构建（推荐）

把本仓当 feed 引入，构建时编进镜像。步骤见 [固件接入](固件接入.md)。

## 方式二：装 apk（手工）

从本仓 Actions 的 artifact `onecloud-upgrade-packages` 取 5 个 apk，或自行构建：

```sh
# 传到设备
scp fwupgrade-*.apk luci-app-onecloud-upgrade-*.apk root@192.168.1.43:/tmp/

# 设备上安装（本地包未签名，必须 --allow-untrusted）
apk add --allow-untrusted --force-overwrite --repositories-file /dev/null /tmp/*.apk
```

`--repositories-file /dev/null` 表示不联网取依赖；依赖（`ucode`、`jsonfilter`、`luci-base` 等）必须已在固件里。

装完重启 rpcd 让对象注册：

```sh
/etc/init.d/rpcd restart
```

菜单在 **系统 → OneCloud 升级**；命令行 `/usr/libexec/fwupgrade/fwupgradectl`。

## 首次使用

1. 打开页面，填「仓库（owner/name）」与两个资产名（默认值是 OneCloud 官方固件仓的命名）；
2. 保持 **演练模式（dry_run）勾选**，点「检测新版本」→ 再点「升级」，观察阶段迁移；
3. 确认无误后，取消演练模式并保存，才会真正写盘。

配置在 `/etc/config/onecloud-upgrade`，字段：`provider` / `repo` / `base_url` / `asset_rootfs` / `asset_boot` / `channel` / `dry_run` / `force`。

## 更新应用之后

覆盖安装新版本 apk 后，**页面要强制刷新一次**（`Ctrl+F5` / 长按刷新按钮选「硬性重新加载」）。

LuCI 的静态资源带 `ETag`/`Last-Modified`，普通刷新可能仍用浏览器缓存里的旧 `overview.js`，表现是「界面还是老样子」——包括已经修好的进度条仍显示旧数字。文件本身已经换了，硬刷即可。

## 备份与回滚

备份有两类来源：

- 本应用在写入前自动产生的 `/opt/fwupgrade/backup/<job>/`（只有 config）；
- 设备脚本已有的 `/opt/upgrade-backup-*/`（含 `config/`，部分还有 `boot-p1.img.gz`）。

```sh
fwupgradectl backups                              # 列出（含来源、时间、大小、内容）
fwupgradectl rollback --confirm <备份ID> --dry-run # 只看差异，不动手
fwupgradectl rollback --confirm <备份ID>           # merge：只覆盖备份里有的文件
fwupgradectl rollback --confirm <备份ID> --replace # 整目录替换（高风险）
fwupgradectl forget --confirm <备份ID> [--force]   # 删除某份备份
```

- **merge 是默认**：只覆盖备份里存在的文件，当前新增的配置不会被删；`--replace` 才整目录替换，会把备份里没有的配置也清掉。
- 每次回滚前先给当前配置打快照 `/etc/config.pre-<ts>/`；恢复后逐文件 `cmp` 校验，不一致即报错。`clean` 只保留最新一份 `.pre-*`。
- **最新一份备份是最后的救援料，默认拒绝删除**，必须显式 `--force`；页面上的删除按钮不带 force，所以删最新会被拒绝并提示走命令行。
- 回滚掉电不会静默：写入前落 `phase=rollback`，中断后 `status` 会显示 `失败 / 混合态 C1` 并给出备份 ID；**直接重跑同一备份的 rollback 即可收敛**（幂等）。

## 诊断包（diag）

```sh
fwupgradectl diag     # → /opt/fwupgrade/diag/fwupgrade-diag-<ts>.tar.gz，页面上也有按钮
```

固定 6 项，全部经过白名单与脱敏：

| 文件 | 内容 |
|---|---|
| `meta.txt` | 时间、主机名、oc-version、uptime、boot_id、phase/last_result、脚本与外壳 sha256、release、df、free |
| `state.json` | 当前状态快照 |
| `config.json` | 生效配置（token 只显示 none / configured） |
| `backups.json` | 可寻址备份列表 |
| `journal-tail.txt` | 日志末 200 行，`token=` / `Authorization=` 已打码 |
| `processes.txt` | 与 fwupgrade 相关的进程 |

**不含** `/etc/config` 任何文件内容、不含密码/私钥/完整 URL 查询串。

## 卸载

```sh
apk del luci-app-onecloud-upgrade fwupgrade-flasher-onecloud fwupgrade-flasher-dryrun fwupgrade-provider-github fwupgrade-core
/etc/init.d/rpcd restart
```

- `/etc/config/onecloud-upgrade` 会被保留（apk 记为配置文件）；想彻底清掉再手动删。
- `/opt/fwupgrade`（状态、日志、备份、诊断）与 `/opt/upgrade-backup-*` 不会被删，按需手动清理。
- 卸载不会动 `upgrade` 脚本与 boot 分区。
