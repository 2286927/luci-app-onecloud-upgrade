# 接入固件构建（feed 方式）

本仓是一个 OpenWrt feed，固件仓不需要内嵌任何包源码，只加一行 `src-git` 与几行 config。

## 1. 加 feed（在 `feeds update` 之前）

`ImmortalWrt-25.12-onecloud.yml` 的 feeds 步骤里，`timeout 1200 ./scripts/feeds update -a` 之前插入：

```sh
# oc-upgrade 应用：独立仓通过 feed 引入
[ -f feeds.conf ] || cp feeds.conf.default feeds.conf
grep -q '^src-git oc-upgrade ' feeds.conf || echo "src-git oc-upgrade https://github.com/2286927/luci-app-onecloud-upgrade.git" >> feeds.conf
echo "feed: $(grep '^src-git oc-upgrade ' feeds.conf)"
```

## 2. 强选 5 个包（在 `make defconfig` 之前）

```sh
OC_PKGS="fwupgrade-core fwupgrade-provider-github fwupgrade-flasher-onecloud fwupgrade-flasher-dryrun luci-app-onecloud-upgrade"
for p in $OC_PKGS; do
  grep -q "^CONFIG_PACKAGE_${p}=y" .config || echo "CONFIG_PACKAGE_${p}=y" >> .config
done
```

## 3. defconfig 后守卫

```sh
for p in $OC_PKGS; do
  grep -qx "CONFIG_PACKAGE_${p}=y" .config || { echo "::error::oc-upgrade 包未入选：$p（feed 或依赖缺失）"; exit 1; }
done
echo "PASS⑱ oc-upgrade 五个包均入选"
```

## 注意

- **`fwupgrade-flasher-dryrun` 必须入选**：应用默认 `dry_run=1`，缺它第一次点升级会报 “flasher 未安装”。
- 所有包 `PKGARCH=all`（纯 shell / ucode / JS），但与目标无关不代表可以不验证：首次构建仍需确认 apk 产物存在。
- 验证时看两行日志：`feed: src-git oc-upgrade ...` 与 `PASS⑱`。
- 如果希望应用随镜像出厂，做到这一步就够了；如果只想发独立 apk，不需要改固件仓，直接从 Actions 产物或本仓 Releases 取。

## 回退

```sh
sed -i '/^src-git oc-upgrade /d' feeds.conf
sed -i '/^CONFIG_PACKAGE_\(fwupgrade\|luci-app-onecloud-upgrade\)/d' .config
```

## 在线升级会把「未随镜像打包」的应用变成孤儿（实测 2026-11-26）

如果镜像里**没有**这 5 个包，设备在线升级后会出现这种状态：

```
VER=26.11.18_16.27.30        # 升级本身成功
PKGS=0                        # apk 里查不到本应用
```

原因：rootfs 包整包覆盖 `/`，其中包含**新的 `/lib/apk/db/installed`**，旧数据库里的本应用记录被整体替换。而 `tar -x` 不会删除「新镜像里没有、旧系统里有」的文件，于是出现：

- **文件还在**：`/usr/libexec/fwupgrade/*`、`/www/luci-static/resources/view/onecloud_upgrade/`、`/usr/libexec/rpcd/luci.onecloud-upgrade`、`/usr/share/luci/menu.d/luci-app-onecloud-upgrade.json` 全部保留，`/etc/config/onecloud-upgrade` 也在，**应用照常能用**；
- **纳管没了**：`apk info -e fwupgrade-core` 返回不存在，`apk del` 清不掉它，`apk upgrade` 也不会更新它；
- **重装要带 `--force-overwrite`**（文件已存在，否则冲突）：

```sh
apk add --allow-untrusted --force-overwrite \
  fwupgrade-core-0.1.0-r1.apk fwupgrade-provider-github-0.1.0-r1.apk \
  fwupgrade-flasher-onecloud-0.1.0-r1.apk fwupgrade-flasher-dryrun-0.1.0-r1.apk \
  luci-app-onecloud-upgrade-0.1.0-r1.apk
```

**结论**：想让应用在升级后仍在 apk 管理之内，必须按本文第 1–3 步把它编进镜像（推荐）；只想发独立 apk 的话，升级后要按上面命令重装一次。两种方式应用功能都不受影响，差别只在「能不能被 apk 管」。
