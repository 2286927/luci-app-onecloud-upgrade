# 开发备忘

写这个应用时踩过的坑与不可见约定，重来一遍还会踩的都在这里。

## LuCI / rpcd 三处坑

### 1. 视图目录不能带连字符

`view/onecloud-upgrade/overview.js` 会让页面**永久停在「正在加载视图…」**，控制台无明显报错。改成 `view/onecloud_upgrade/overview.js` 立即正常。

菜单 key、包名、文件名都可以带连字符，**只有 view 目录路径不行**。排查这类"白屏/转圈"时先看这个。

### 2. rpcd exec 插件的调用约定

不是「无参枚举 + 方法名作为 argv[1]」，而是：

```sh
# list：输出方法清单
# call <method>：从 stdin 读 JSON 参数，stdout 输出 JSON
```

原来只处理了无参分支，结果是对象注册成功（`ubus -S list` 看得到）但方法列表为空，`ubus call` 返回 253。

### 3. 同一个 rpcd 对象的并发调用会互相卡住

视图里 `load()` 用 `Promise.all([status, config_get])` 会一直转圈。改成顺序 `.then()` 链即正常。需要并发时，不同方法各自独立请求、不要共用一个未完成的 promise。

## 打包

- **不要用 `luci.mk`**：本仓没有 `feeds/luci` 上下文时，SDK 里 `luci.mk` 不可用，`make package/.../compile` 会报 `No rule to make target`。全部用 `rules.mk` + `package.mk` + 显式 `install`。
- 产物必须是 `noarch`（`PKGARCH:=all`），5 个包一个不能少；CI 里产物数量不等于 5 直接失败。
- 包名与配置名不一致是故意的：包装成 `fwupgrade-*`，UCI 配置叫 `onecloud-upgrade`，各命令里 `uci get onecloud-upgrade.main.*`。

## 状态与并发

- 状态真值在 `/opt/fwupgrade/state.env`（KEY=VALUE），`state.json` 是渲染出来的派生文件，不要手改 JSON。
- 状态写入用 `$$` 后缀的唯一临时文件 + 原子 `rename`；设备上**没有 `flock`**，所以并发靠「唯一临时文件 + 最后写入者胜出」，不是靠锁。
- 阶段锁文件是 `/var/run/fwupgrade.lock`，内容 `pid boot_id phase`。`writing_boot` 阶段即使发现 pid 已死也**拒绝自动继续**——那意味着可能写了一半。
- 回滚写 `/etc/config` 有三个不能省的约束：先落 `phase=rollback` 标记、逐文件「临时名 + rename」、`--replace` 用旁路目录构建并校验后再两次 rename 切换。

## 本地调试

```sh
sh tests/test_core.sh                                  # 60 条，不需要设备
OC_HOST=<设备IP> python3 tools/probe_status.py         # 只读取证
```

设备上手工验证：

```sh
apk add --allow-untrusted --force-overwrite --repositories-file /dev/null /tmp/*.apk
/etc/init.d/rpcd restart                               # 让 rpcd 对象重新注册
/usr/libexec/fwupgrade/fwupgradectl status
```

改完 JS 视图要清浏览器缓存或强刷；`view/*/overview.js` 的改动不会被 LuCI 缓存重写，但 `menu.d/*.json` 需要重启 rpcd。
